# promethean_prm35 — пульт проектора на ТВ-приставке

Android-приложение «Проектор» для синего GT-King Pro (Android 9). Управляет проектором
Promethean PRM-35, который подключён к приставке кабелем: приставка ходит к нему на
`192.168.77.2:8000` по его текстовому протоколу (`~` + команда + `\r`).

Приложение делает три вещи:

- показывает пульт на экране телевизора, кнопки переключаются стрелками пульта приставки, OK
  нажимает. Рядом QR-код с адресом веб-пульта, чтобы открыть его с телефона;
- отдаёт тот же пульт веб-страницей: `http://10.31.41.106:8070/`;
- публикует MCP-сервер для агента на приставке (androidclaw, репозиторий
  `~/Data/Projects/androidclaw`): `http://127.0.0.1:8070/mcp`.

Сервер живёт в foreground-сервисе и стартует при загрузке приставки, так что веб-пульт и MCP
работают, даже если приложение не открывали.

## Решения

- Одно приложение на приставке: «приложение для андроида простое, которое показывает на экране пульт и позволяет управлять им через веб-интерфейс».
- MCP для агента — в том же приложении: «это приложение должно публиковать mcp для агента, который живет на приставке, чтобы он мог управлять проектором».
- QR-код с адресом: «пусть показывает qr код с адресом и портом при запуске приложения, чтобы можно было быстро перейти».
- Звука нет: «у проектора вообще нет ни динамиков, ни выхода».
- Отдельный проект с именем проектора: «вынеси это в отдельный проект, и назови по названию проектора».

## Сборка и установка

```bash
make apk                          # build/projector-remote.apk
make install TV=10.31.41.106:5555 # собрать, поставить через adb и запустить
make logs                         # строки лога приложения
```

Сборка идёт в Docker (образ `cimg/android` с SDK, без Gradle: aapt2, javac, d8, zipalign,
apksigner). Docker может смотреть на удалённый демон, поэтому APK достаётся из контейнера через
`docker cp`, а не через монтирование. Подпись — отладочным ключом `debug.keystore` из репозитория
(пароль `android`), чтобы переустановка поверх работала без удаления.

Автозапуск при загрузке срабатывает, только если приложение хоть раз открывали после установки:
`make install` его открывает.

## Адреса

| Адрес | Что |
| --- | --- |
| `GET /` | пульт |
| `POST /api/cmd` | команда проектору: `c=<команда>` в теле формы или в строке запроса, ответ `{"reply": "..."}` |
| `GET /api/status` | `{"power": "On", "input": "HDMI", "lamp_hours": "375"}` |
| `GET /api/info` | адрес пульта для телефона: `{"url": "http://10.31.41.106:8070/"}`, берётся с wlan0 |
| `POST /mcp` | MCP (Streamable HTTP, ответы JSON, без сессий) |

```bash
curl -X POST 'http://10.31.41.106:8070/api/cmd?c=~qL'
curl -X POST http://10.31.41.106:8070/mcp -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"projector_status","arguments":{}}}'
```

Инструменты MCP: `projector_status` (питание, вход, часы лампы), `projector_power`
(`state`: `on`/`off`), `projector_command` (любая команда протокола; таблица команд — в
описании инструмента, [Mcp.java](src/xyz/vvzvlad/projectorremote/Mcp.java)).

## Проектор

- Одна команда на одно TCP-соединение, ответ — значение до `\r`. Все обращения идут по очереди,
  с паузой 200 мс между ними.
- Проектор сбрасывает примерно каждое второе соединение: закрывает его сразу, без ответа, и
  команду не выполняет. Следующее соединение проходит, поэтому сброшенная команда повторяется
  (до трёх попыток).
- `~PN` включает только из дежурного режима: после выключения лампа должна остыть.
- Динамиков у проектора нет, кнопок звука на пульте нет.

## Что где на приставке

| Что | Где |
| --- | --- |
| пакет | `xyz.vvzvlad.projectorremote` |
| порт | 8070 на всех интерфейсах. Порт 8000 на wlan0 занят: он пробрасывается на проектор |
| маршрут к проектору | `192.168.77.0/24` через lan0 (правило `ip rule` с приоритетом 9000 ставит `projector-net.sh`) |
| лог | `adb logcat -s ProjectorRemote` |
| сеть проектора | `/data/local/projector-net.sh`, запускается службой init `projector_net` из `/system/etc/init/projector-net.rc` по `sys.boot_completed=1` |
| аренда DHCP и stdin dnsmasq | `/data/local/tmp/projector-dnsmasq.leases`, `/data/local/tmp/projector-dnsmasq.stdin` |

## Сеть проектора на приставке

Проектор подключён к порту Ethernet приставки, сама приставка в сети по Wi-Fi. Сеть для него
поднимает [box/projector-net.sh](box/projector-net.sh) при загрузке ([box/projector-net.rc](box/projector-net.rc)):

- переименовывает `eth0` в `lan0`: системная служба Ethernet берёт только `eth<N>` и иначе
  запускала бы там DHCP-клиент и сбрасывала адрес;
- ставит на `lan0` 192.168.77.1/24, правила `ip rule` 9000 (`to 192.168.77.0/24 lookup main`) и
  9001 (`iif lan0 lookup wlan0`), включает `ip_forward`;
- пробрасывает TCP 8000 с wlan0 на 192.168.77.2:8000 (DNAT в `oem_nat_pre`, разрешение в `oem_fwd`,
  маскарадинг в `lan0`), так что проектор доступен из домашней сети как `10.31.41.106:8000`;
- запускает dnsmasq, который выдаёт проектору единственный адрес 192.168.77.2. Android-сборка
  dnsmasq ждёт команд netd на stdin и на `/dev/null` крутится на 100% CPU, поэтому stdin ей
  отдаётся FIFO, открытый на чтение и запись.

Установка: скрипт — `adb push box/projector-net.sh /data/local/`, служба — после
`mount -o remount,rw /` скопировать `box/projector-net.rc` в `/system/etc/init/` (права 644), затем
`mount -o remount,ro /` и перезагрузка.

# promethean_prm35 — факты и решения

Проверенные факты о проекторе и приставке, на которых стоит приложение, и варианты, которые
отвергнуты. Как собрать, поставить и что где лежит — `README.md`.

## Проектор

- Promethean PRM-35, MAC 00:18:23:22:66:5C (OUI Delta Electronics — производитель Vivitek),
  прошивка `DP576-332PT-DPP04` (ответ на `~qV`). DHCP в проекторе включён по умолчанию: без
  сервера он шлёт DHCP Request раз в 2 с (видно `tcpdump -i eth0` на приставке).
- Порты: 8000 — управление, 80 — веб-интерфейс на Flash, 23 — закрыт (SYN без ответа), хотя
  мануал называет «23 or 8000». PJLink (4352) не отвечает.
- Протокол — статья Promethean «PRM-25 command codes», помеченная и для PRM-35:
  <https://support.prometheanworld.com/s/article/1436> (таблицы в ней — картинки). `~` + команда +
  CR; запрос `~q<X>` возвращает значение строкой с CR (`~qP` → `On`/`Off`, `~qS` → `HDMI`,
  `~qL` → `375`), `~PN` → `P`, неизвестная команда → `N`.
- Ответ приходит, только если соединение держать открытым ~1 с после команды:
  `printf '~qP\r' | nc …` возвращает пусто, `(printf '~qP\r'; sleep 1) | nc …` — `On`.
- `~PN` включает только из дежурного режима. После `~PF` проектор отвечает `Off` через 5 с,
  `~PN` через ~65 с после выключения сработал: `P`, затем `On` через ~35 с прогрева.
- Проектор сбрасывает примерно каждое второе соединение: закрывает сразу, без байта ответа.
  Замер при разработке приложения (не перепроверялся), `~qP` по 16 попыток: пауза 0,2 с — 8 из 16 успешно, 0,5 с — 8, 1 с — 9, 2 с — 6, 3 с — 12;
  чередование почти строгое. Четыре команды в одном соединении — ответ максимум на первую.
  Сброшенный `~qP` позже в чужом соединении не всплывал, поэтому приложение повторяет команду
  на пустом ответе (до трёх попыток). Для команд, меняющих состояние, это не проверялось.
- Изредка проектор присылает искажённый ответ: «5» и «ormal» в замере кодера, «ff» на `~qP`
  у агента 2026-11-02 при включённом проекторе. 30 запросов `~qP` подряд после этого вернули
  `On` все 30. Причина не найдена.

## Приставка

- GTKing_PRO, slimBOXtv на Android 9 (API 28), root, SELinux permissive, adb без подтверждения на
  10.31.41.106:5555. Экран 1920×1080 при плотности 240 — страница видит 1280×720. WebView —
  `com.android.webview` 103.0.5060.71.
- В сеть приставка ходит по Wi-Fi (`wlan0`), порт Ethernet отдан проектору.
- Системная служба Ethernet Android 9 берёт только интерфейсы `eth<N>` и при пустом DHCP
  перезапускает на них DHCP-клиент, который сбрасывает адреса. Поэтому `projector-net.sh`
  переименовывает `eth0` в `lan0`.
- netd маршрутизирует по таблицам на каждую сеть и `ip rule` с fwmark; трафик к 192.168.77.0/24
  и ответы с `lan0` проходят только благодаря правилам 9000 и 9001 перед правилами netd.
  `tetherctrl_FORWARD` заканчивается DROP, разрешение для проброса стоит в `oem_fwd`.
- Android-сборка dnsmasq делает `select` на stdin, ожидая команд netd. На `/dev/null` она
  крутилась на 100% одного ядра (strace: `read(0)=0` / `pselect … in [0]` по кругу), поэтому
  stdin ей — FIFO, открытый на чтение и запись.
- slimBOXtv при загрузке запускает скрипты из `/data/media/0/init.d` (так стартует tv-agent);
  `projector_net` запускается своей службой init из `/system/etc/init/projector-net.rc`.
- Перезагрузка 2026-11-02 подтвердила автозапуск: `projector_net` поднял сеть, приложение
  стартовало по `BOOT_COMPLETED`. Через ~50 с после загрузки приставки соединение на 8000 ещё
  не проходило (connect timeout), хотя аренду проектор уже получил; через ~2 мин проходило.

## Отвергнутые варианты

- **Мост Ethernet ↔ Wi-Fi на приставке.** Клиент Wi-Fi в обычном режиме не пропускает кадры с
  чужим MAC, точка доступа их отбросит; нужен 4addr/WDS на обеих сторонах. Вместо моста —
  маршрутизация с DNAT порта 8000.
- **Протокол Vivitek `V99S0001`/`op …`.** Мануал PRM-35 дословно повторяет мануалы Vivitek, но
  проектор на эти коды отвечает `N` или мусором.
- **Gradle.** Решено при разработке: сборка обычными build-tools (aapt2, javac, d8, apksigner) в
  Docker, без системы сборки.
- **`docker build --output`.** На ноутбуке нет buildx, APK достаётся через `docker cp`.
- **Кнопки звука.** У проектора нет динамиков и выхода.
